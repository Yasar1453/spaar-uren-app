# 3. AANSLUITEN
############################################################################

De module heeft één regel nodig in het bijbehorende script. Die twee bestanden
zijn in beheer van een andere agent; dit is wat erin moet:

--- 3a. app/beheer.js — bij de andere imports bovenaan --------------------

  import { bouwRoosterExtra } from "./rooster-extra.js?v=42";

--- en onderaan naarDash(), na de bestaande laad-aanroepen ----------------

  // Rooster-uitbreiding: open diensten, beschikbaarheid, ruilen, dagweergave.
  bouwRoosterExtra(db, { esc, toonMeld, rijLeeg, kleurVan, werkbonTekst, haalAlles, isoDatum, ikBenId: () => ikBenId });

--- 3b. app/monteur.js — bij de andere imports bovenaan -------------------

  import { bouwRoosterMonteur } from "./rooster-extra.js?v=42";

--- en in naarStatus(), na het ophalen van `mij` --------------------------

  bouwRoosterMonteur(db, { esc, netfout, toonMelding, mij: () => mij });

Alle sleutels van dat tweede argument zijn optioneel: ontbreekt er een, dan
gebruikt de module zijn eigen versie. Dat is met opzet — een ontbrekende
hulpfunctie mag nooit een leeg rooster opleveren.

Wil je helemaal niets in beheer.js of monteur.js aanraken, dan kan het ook met
een los blokje onderaan de HTML, vlak voor </body>:

  <script type="module">
    import { beheerClient } from "./config.js?v=42";
    import { bouwRoosterExtra } from "./rooster-extra.js?v=42";
    // Let op: dit maakt een tweede clientinstantie op dezelfde opslagsleutel.
    // Werkt, maar de variant hierboven (3a) is netter.
    bouwRoosterExtra(beheerClient(), {});
  </script>

De module laadt zichzelf zodra er een sessie is, en opnieuw bij elke klik op
het tabblad Rooster (`.nav[data-tab="rooster"]` in beheer, `[data-mnav="rooster"]`
in de monteur-app). Verder is er geen aanroep nodig.
